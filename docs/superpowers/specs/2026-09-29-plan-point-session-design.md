# 포인트 훈련 — 대회 계획 주차표 · 아침 제안 · 대회 없을 때 설계

> 상태: 결정 확정 (2026-09-29). 결정 전부 권장안. 코드 변경 없음.
> 80/20 보류는 이 문서 범위만큼 푼다: 대회 계획의 포인트 칸, 대회 없을 때 다음 세션 종류 제안. 이지 확인·주간 강도 예산·초보 강도 해석은 계속 보류.
> 계기: 마라톤 35km 벽 영상(회색 지대 조깅·버티기 훈련 부재·속도 훈련 분리) 검토 → 앱 계획에 "무엇을 어떤 강도로"가 없다는 결론.
> 관련: 2026-09-22 아침 제안 · 2026-09-23 계획 세션 제안 · 고강도 판정 유지 결정 · 80/20 보류 결정.

## 1. 목적

지금 계획은 한 주를 "롱런 1회 + 이지 N회"로만 나눈다. 얼마나 뛸지는 말하지만 **어떤 강도로 뛸지는 말하지 않는다.**
그래서 매번 페이스를 보며 존 4~5로 달리는 습관을 앱이 막지 못한다.

이 설계는 한 주에 **포인트 1회**를 넣는다. 포인트는 강도를 의도적으로 올리는 날이다. 나머지는 이지로 분리한다.
- **내일(아침 제안)**: 강도 OK인 날에 이번 주 포인트를 권한다.
- **과거(주차표)**: 포인트를 했는지 노랑으로 보여준다.

원칙은 2026-09-23 설계와 같다. HRV와 부하는 문을 열고 닫는다. 종류는 계획이 정한다. 처방보다 설명이 먼저다.

## 2. 용어

| 사용자에게 보이는 말 | 뜻 | 포함하는 저장 유형 |
|---|---|---|
| **이지** | 편하게, 대화 가능한 강도 | 이지런 · LSD · 일반 |
| **롱런** | 주에 한 번 가장 긴 러닝 | 롱런 (후반 대회 페이스 포함) |
| **포인트** | 강도를 의도적으로 올린 러닝 | 인터벌 · 템포 · 빌드업 · 거리주 · 대회 |

"포인트 훈련"은 국내 러너가 쓰는 말이다. 포인트에 포함하는 유형은 고강도 판정(`RunSummaryBuilder.isHardRun`)의 종류 규칙과 같다. 판정 규칙은 바꾸지 않는다.

## 3. 포인트 종류 — 계획 단계가 고른다

| 단계 | 포인트 종류 | 내용 (워밍업·쿨다운 포함 총 거리) | 페이스 기준 |
|---|---|---|---|
| 늘리기 | **속도** | 워밍업 2km + 1km × R회 (사이 2분 조깅) + 쿨다운 1km | 5K 예측 페이스 |
| 유지 | **템포** | 워밍업 2km + T km 지속 + 쿨다운 1km | 10K와 하프 예측 페이스의 중간 |
| 대회 페이스 | **빌드업** | B km, 편하게 시작해 마지막 3분의 1을 대회 페이스로 | 훈련용 대회 페이스 |
| 테이퍼 | **짧은 대회 페이스** | 워밍업 2km + 대회 페이스 1km × 3회 (사이 400m 조깅) + 쿨다운 1km | 훈련용 대회 페이스 |
| 회복 | 없음 | | |
| 대회 주 (튠업) | 대회 자체가 포인트 | 별도 칸 없음 | |
| ○○ 계획 (따르는 주) | 따르는 계획의 포인트 그대로 | | |
| D-7 이내 | 없음 | D-day 카드가 담당 | |

**양 정하기** (전부 이번 주 주간 km 기준)
- R = 반올림(주간 km × 0.08), 3~6회로 자른다. Daniels의 "인터벌 빠른 구간은 주간 거리의 8% 이하" 관행을 따른다.
- T = 반올림(주간 km × 0.10), 3~8km로 자른다. Daniels의 "역치 구간은 주간 거리의 10% 이하" 관행을 따른다.
- B = 10K 계획 8km · 하프 10km · 풀 14km. 단 롱런의 70%를 넘지 않는다. ⚠ 임의로 정함.

**페이스**
- 예측 기록(`halfEquivMin`)에서 Riegel 1.06으로 5K·10K 페이스를 낸다. 대회 페이스는 기존 `mrTrainingRacePaceSecPerKm`을 그대로 쓴다.
- 목표 기록이 아니라 예측 기록 기준이다. 기온 보정 전 값이다. 기존 대회 페이스 표시와 같은 규칙이다.
- 템포 페이스를 10K와 하프의 중간으로 둔 것은 임의다. Daniels의 T 페이스는 "1시간 대회 페이스"인데, 일반 러너에게 1시간 대회는 대략 10K와 하프 사이다.

**근거 수준**
- 강도 분리(쉬운 날은 쉽게, 강한 날은 강하게) 자체는 근거가 있다. Stöggl & Sperlich 2014 (Front Physiol 5:33)에서 9주 양극화 훈련이 역치 위주·고강도 위주·볼륨 위주보다 향상이 컸다.
- 단계별 종류 배정, 회수, 거리는 코칭 관행이다. 통제 연구로 정해진 값이 아니다. 코드 주석에 그대로 적는다.
- 테이퍼 중 강도 유지는 Bosquet 2007이다. 지금 문구 "강도는 그대로"에 실체가 생긴다.

## 4. 빈도 — 주당 러닝 횟수로 정한다

계획은 이미 본인 최근 4주 러닝 빈도(`runsPerWeek`)를 쓴다. 포인트 빈도도 여기서 정한다.

| 최근 주당 러닝 | 포인트 |
|---|---|
| 4회 이상 | 매주 1회 |
| 3회 | 2주에 1회. 계획 첫 늘리기 주부터 번갈아. 테이퍼 주는 항상 |
| 2회 이하 | 넣지 않는다. 롱런 + 이지만 |

- 포인트는 이지 한 번을 대신한다. 주간 km와 러닝 횟수는 그대로다.
- 이지 1회 거리 = (주간 km − 롱런 km − 포인트 km) ÷ 이지 횟수. 이 값이 1.5km 아래로 내려가면 그 주는 포인트를 넣지 않는다.

**레벨 대신 주당 횟수를 쓰는 이유**
- 엔진에는 비공개 레벨(`LevelBucket`)이 없다. 레벨은 앱 쪽에서 계산된다.
- 레벨을 엔진에 넣으면 주입 경로가 하나 더 생긴다. 고강도 판정 불일치와 확정 주차 누락이 모두 이 경계에서 났다.
- 주 2회 이하로 뛰는 사람은 대체로 입문자라, 횟수가 레벨을 충분히 대신한다.
- 대안: 초보 버킷만 엔진에 넘겨 포인트를 끄는 방법. 결정 2 참조.

## 5. 데이터 — 주차에 구조화된 칸 하나

```swift
struct MRPlanPoint: Codable, Equatable {
    enum Kind: String, Codable { case speed, tempo, buildUp, racePaceShort }
    let kind: Kind
    let totalKm: Double          // 워밍업·쿨다운 포함
    let reps: Int?               // speed · racePaceShort
    let repKm: Double?           // speed 1.0 · racePaceShort 1.0
    let sustainedKm: Double?     // tempo T · buildUp 마지막 1/3
    let paceSecPerKm: Double     // 빠른 구간 페이스
}

struct MRPlanWeek { …; var point: MRPlanPoint? = nil }
struct MRPlanWeekSummary: Codable { …; var point: MRPlanPoint? }   // decodeIfPresent → 옛 스냅샷은 nil
```

- **안내 문구(`breakdown`)에는 포인트를 넣지 않는다.** 이지 횟수만 하나 줄어든다. 예: "롱런 16km + 이지 6km × 2회".
  - 이유 1: 아침 제안이 이 문구를 정규식(`mrParsePlanBreakdown`)으로 읽는다. 포인트 문구가 섞이면 이지 횟수를 잘못 읽을 수 있다.
  - 이유 2: 영어 변환(`localizedBreakdown`)이 "회"를 "x"로 통째로 바꾼다. "1km × 3회"류 포인트 문구가 망가진다.
- 포인트 문구는 `MRPlanPoint`에서 화면이 그 자리에서 만든다. 한국어·영어를 각각 만든다.
- 스냅샷을 거치는 모든 곳(`MRPlanGovernance.applyingSnapshot`, 따르는 주 복사, 스토어의 확정 주차)에서 `point`를 함께 옮긴다. 계획 주차 숫자를 말하는 카드는 모두 applyingSnapshot을 거친다는 기존 규칙을 따른다.

## 6. 이미 시작한 계획 — 다음 주부터 채운다

진행 중인 계획은 바꾸지 않는 게 원칙이다. 포인트는 롱런과 주간 km를 바꾸지 않고 이지 한 번의 성격만 바꾼다. 그래서 아래처럼 한 번만 채운다.

- **지난 주와 이번 주**: 그대로 둔다. 포인트 칸이 없고, 포인트 이행도 표시하지 않는다.
- **다음 주부터**: 스냅샷 주차에 `point`가 없으면 실시간 계획의 `point`와 줄어든 이지 횟수 문구로 채운다. 새 트리거 5로 둔다. 로그: `[스냅샷] 포인트 칸 채움 → N주`.
- 한 번 채운 뒤에는 기존 트리거 0·3·4 규칙을 따른다.
- **이번 주의 공백**: 이번 주는 아침 제안도 포인트를 권하지 않는다. 계획 주차가 오늘을 덮고 있으므로 9절 대회 없음 모드도 쓰지 않는다. 한 주 공백은 받아들인다. 주 중간에 계획 문구와 이지 횟수가 바뀌면 이미 뛴 날의 셈이 어긋나기 때문이다.
- 채운 주라도 단계 규칙은 그대로다. 회복·대회 주·D-7 이내 주는 채워도 포인트가 없다.
- 대회 삭제·복원 때 스냅샷을 무손실로 되살리는 규칙은 그대로다. `point`도 함께 저장되므로 따로 할 일이 없다.

## 7. 주차표 표시 ⚠ 화면 변경 — 실기기 확인 후 확정

안내 문구 줄 아래에 포인트 한 줄을 더한다.

```
 5  10/05  늘리기   롱런 16km + 이지 6km × 2회
                   포인트 · 속도 1km × 4회 5'05"        ← 계획: 흰색 0.72
                   포인트 ✓ 10/08 인터벌                ← 한 뒤: 노랑 (실제로 한 것)
```

- **했는지 판정**: 그 주 러닝 중 롱런으로 센 러닝이 아니면서, 고강도(`hardRunStarts`)이거나 저장 유형이 포인트 유형(인터벌·템포·빌드업·거리주·대회)인 것이 있으면 포인트 완료다. 판정 함수 하나(`mrPointRun`)를 주차표와 아침 제안이 같이 쓴다.
  - 고강도 목록은 최근 15일만 담는다. 지난 주차 판정을 위해 앱이 최근 180일의 포인트 유형 러닝을 `[Date: WorkoutType]`으로 함께 넘긴다(`updatePointRunTypes`).
  - 롱런으로 센 러닝 = 거리 ≥ 롱런 × 0.8인 러닝 중 가장 긴 것 하나.
  - 롱런 · 빌드업 하나만 뛴 주는 롱런이 우선이다. 포인트는 미완료로 남는다.
- **기존 이행 기호(● ◐ ○ ▲)는 바꾸지 않는다.** 롱런·주간 km 두 기준 그대로다. 포인트까지 섞으면 과거 기호의 뜻이 바뀌고 대회 기록 화면의 집계도 흔들린다.
- 노랑은 실제로 한 값에만 쓴다는 규칙대로, 완료 줄만 노랑이다.

## 8. 아침 제안 연결

`MRPlanWeekContext`에 `point: MRPlanPoint?`를 더한다. `mrSessionSuggestion`의 판정을 아래처럼 늘린다.

**이번 주 셈**
- 롱런 완료: 기존대로.
- 포인트 완료: 7절과 같은 규칙.
- 이지 완료: 이번 주 러닝 수 − 롱런 완료 − 포인트 완료, 이지 횟수 상한.

**강도 OK 날의 우선순위**
1. 롱런이 남았고, 오늘이 습관 롱런 요일이거나 남은 날이 2일 이하 → **롱런**. 기존과 같다.
2. 포인트가 남았고, 오늘이 습관 롱런 요일 전날이 아니고, 남은 날이 3일 이상 → **포인트**.
   - 전날 금지 이유: 포인트 다음 날 아침 제안은 고강도 판정 때문에 이지를 권한다. 그러면 롱런이 밀린다.
   - 남은 날 조건 이유: 주 끝에 롱런과 포인트를 몰아넣지 않는다.
3. 그 외 → **이지**. 왜 문장 끝은 기존 규칙 그대로 "여유는 ○요일 롱런에 쓰세요"다. 포인트 상태는 진행 줄에만 보인다.

**이지·휴식 날**: 세션은 기존과 같다. 진행 줄에 포인트 상태만 더한다. 남은 날이 2일 이하인데 포인트가 남았으면 "포인트는 이번 주 건너뛰어도 괜찮아요"를 붙인다. 포인트는 다음 주로 미루지 않는다. 몰아서 두 번 하게 만들지 않기 위해서다.

**문구 예시**

```
오늘은 강도 OK · 포인트 속도 1km × 4회 5'05"
HRV 어젯밤 31ms(평소 범위) · 마지막 고강도 4일 전 · …
이번 주 롱런 아직 · 포인트 아직 · 이지 1/2회
```

```
오늘은 이지 6km · 강도 여유 있음
… 여유는 토요일 롱런에 쓰세요.          ← 금요일, 롱런 전날이라 포인트 대신 이지
이번 주 롱런 아직 · 포인트 아직 · 이지 1/2회 · 3일 남음
```

```
오늘은 이지런 · 이지 6km
어제 고강도 …
이번 주 롱런 아직 · 포인트 완료 · 이지 1/2회
```

- **테이퍼 주 예외**: 아침 제안의 기존 규칙 1은 테이퍼 주를 무조건 이지로 판정했다. 이번 주 포인트가 남았고 **오늘 그 포인트를 권할 수 있는 날**(대회 7일 밖 · 남은 날 3일 이상 · 롱런 습관 요일 전날 아님)이면 이 규칙을 건너뛰고 일반 규칙으로 판정한다. 그 밖의 테이퍼 날은 기존대로 이지다.
- **D-day 카드**: 이번 주 계획 문구 뒤에 " + 포인트 …"를 붙인다(이지 횟수가 하나 줄어 있어 빼고 말하면 합이 안 맞는다).
- 포인트를 한 다음 날은 고강도 판정이 그대로 "어제 고강도 → 이지"를 낸다. 새 규칙이 필요 없다.
- 세션 문자열은 `MRReadiness.session`에 들어간다. 판정 줄 형식은 기존 "판정어 · 세션"을 그대로 쓴다.

## 9. 대회가 없을 때 — 2주 리듬

오늘을 덮는 계획 주차가 없으면 이 모드다. 등록한 대회가 없을 때, 대회는 있지만 계획 시작일 전일 때, 마지막 대회가 끝나고 다음 대회가 없을 때가 모두 해당한다.
지금은 이때 아침 제안이 강도 판정 한 줄만 낸다.

**목적은 늘리기가 아니라 유지하며 리듬 지키기다.** 향할 날짜가 없으니 10% 증가도 테이퍼도 없다. 주차표도 없다. 아침 제안 한 곳에서만 말한다.

### 9.1 세 요소

| 요소 | 기준 | 마지막으로 한 날 판정 |
|---|---|---|
| **롱런** | 평소 롱런 L = 최근 4주 주별 최장 러닝의 중앙값. 늘리지 않는다. L이 8km 미만이면 롱런 개념 없이 이지만 | 거리 ≥ L × 0.8인 러닝 |
| **포인트** | 4절 빈도 규칙과 같다. 주 4회 이상은 7일, 주 3회는 14일, 주 2회 이하는 없음 | 고강도 러닝(`isHardRun`) 중 롱런으로 센 것이 아닌 러닝 |
| **이지** | 나머지 전부 | |

- 주당 러닝 횟수는 계획과 같은 `runsPerWeek`(최근 4주)를 쓴다.
- 대회 모드와 같은 포인트 정의와 같은 빈도 규칙을 쓴다. 두 모드가 다른 말을 하지 않게 하기 위해서다.

### 9.2 포인트 종류 — 번갈아

계획 단계가 없으니 지난 포인트의 다음 종류를 권한다. 순서는 **속도 → 템포 → 빌드업 → 속도**다.

| 지난 포인트의 저장 유형 | 다음에 권할 종류 |
|---|---|
| 인터벌 | 템포 |
| 템포 | 빌드업 |
| 빌드업 · 거리주 | 속도 |
| 없음 (최근 8주에 포인트 없음) | 빌드업. 가장 부담이 적고 영상이 중심에 둔 종류다 |

- 양은 3절 공식을 쓰되, 주간 km는 최근 4주 평균 주간 km로 둔다.
- 빌드업 거리는 min(10km, L × 0.7)이다. 마지막 3분의 1은 하프 예측 페이스다. ⚠ 임의로 정함. 대회 거리가 없어서 하프를 기준으로 삼았다.
- 속도·템포 페이스는 3절과 같이 예측 기록에서 낸다.
- 테이퍼용 "짧은 대회 페이스"는 이 모드에서 쓰지 않는다.

**엔진이 지난 포인트의 종류를 알아야 한다.** 지금 앱은 엔진에 고강도 러닝의 시작 시각 집합만 넘긴다(`updateHardRunStarts`).
같은 홈 함수(`pushHardRunStarts`)에서 최근 180일 포인트 유형 러닝의 `[Date: WorkoutType]`을 함께 넘긴다(`updatePointRunTypes`). 고강도 집합과 그 쓰임은 바꾸지 않는다. 유형 조회는 `workoutTypeLookup()`으로 UserDefaults를 한 번만 읽는다.

### 9.3 대회 뒤 2주 회복

확정된 대회(등록 대회 또는 저장 유형 대회)가 1~13일 전이면 포인트도 롱런도 권하지 않는다. 판정이 강도 OK여도 세션은 이지이고 판정 줄은 "오늘은 이지런 · 대회 뒤 회복"이다. 대회 당일은 세지 않는다.

**대회 앞 2주**: 등록 대회가 오늘~13일 뒤에 있으면(계획 없이 3주 안에 등록한 대회) 리듬을 쓰지 않는다. D-day 카드가 테이퍼를 말하는데 리듬이 롱런·포인트를 권하면 두 카드가 부딪힌다.
왜 문장: "○○ 대회 N일 뒤 — 2주는 이지로 회복해요." 다음 대회 계획이 이미 시작됐으면 계획의 회복 주가 우선하므로 이 규칙은 쓰지 않는다.
⚠ 14일은 코칭 관행이다. 대회 거리별로 나누지 않는다.

### 9.4 아침 제안 우선순위

강도 OK인 날:
1. 대회 뒤 14일 안 → **이지**.
2. 마지막 롱런이 7일 이상 전이고, 오늘이 습관 롱런 요일이거나 습관 요일이 없을 때 → **롱런 L km**.
3. 마지막 포인트가 빈도 간격 이상 전이고, 오늘이 습관 롱런 요일 전날이 아니다 → **포인트** (9.2 종류).
4. 그 외 → **이지**.

이지·휴식 날은 판정과 세션이 지금과 같다. 셋째 줄에 리듬 상태만 더한다.

```
오늘은 강도 OK · 포인트 추천: 속도 1km × 4회 5'05"
지난 포인트는 9/24 빌드업, 8일 전이에요. …
마지막 롱런 5일 전 · 마지막 포인트 8일 전
```

```
오늘은 이지런 · 이지
춘천마라톤 6일 뒤 — 2주는 이지로 회복해요. …
```

- 이지 거리는 말하지 않는다. 대회 모드와 달리 주간 목표가 없어서 나눌 기준이 없다. 주간·월간 목표 거리를 넣지 않는다는 결정과도 맞다.
- 롱런 L과 포인트 양은 본인 최근 4주에서 나온 값이라, 늘리라는 말이 아니라 평소를 지키라는 말이다.

## 10. 결정 (전부 권장안으로 확정, 2026-09-29)

1. **포인트 종류 배정** (3절 표). 권장: 표대로. 대안은 대회 페이스 단계에서 빌드업 대신 "대회 페이스 지속주"를 쓰는 것이다. 빌드업은 앱이 이미 분류하고 영상도 중심에 두기 때문에 빌드업을 권한다.
2. **빈도 기준** (4절). 권장: 주당 러닝 횟수만. 대안은 초보 버킷을 엔진에 넘겨 포인트를 끄는 것이다.
3. **시작한 계획에 채우기** (6절). 권장: 다음 주부터 채움. 대안은 새로 만드는 계획에만 넣는 것이다. 그러면 지금 진행 중인 하프·풀 계획에는 포인트가 생기지 않는다.
4. **주차표 포인트 줄 모양** (7절). 화면 변경이라 실기기에서 보고 확정한다.
5. **대회 없을 때 롱런** (9.1). 유지. 대안이던 2주마다 1km 증가는 쓰지 않는다.
6. **대회 없을 때 간격** (9.1). 롱런 7일, 포인트는 4절 빈도 규칙.
7. **포인트 종류 번갈이** (9.2). 넣는다. 기존 고강도 주입 경로에 유형만 붙인다.
8. **대회 뒤 2주 회복** (9.3). 넣는다.

## 11. 범위 밖

- **이지가 정말 이지였는지 확인하는 기능.** 80/20 보류로 남긴다. 주간 강도 예산·초보 강도 해석도 보류.
- 대회 없을 때의 주간 표나 목표 거리. 아침 제안 한 줄로만 말한다.
- 언덕 인터벌, 10km TT. 페이스로 안내하기 어렵고 이행을 판정하기 어렵다.
- 대회 기록 화면(아카이브)의 포인트 이행 집계.
- 고강도 판정 규칙 변경. 유지 결정대로 건드리지 않는다.
- 근력 운동 안내. 내구성 조언 카드가 이미 담당한다.

- 아침 제안: 강도 OK 우선순위 1·2·3 · 롱런 요일 전날 포인트 금지 · 남은 날 2일 이하 문구 · 롱런 · 빌드업 하나만 뛴 주의 셈 · 포인트 다음 날 이지.

- 주입: `[Date: WorkoutType]`으로 바꾼 뒤 기존 고강도 개수 셈이 같은 값.
