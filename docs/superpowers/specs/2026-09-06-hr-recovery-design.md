# 운동 후 심박수(회복) — 상세 패널 · 성장 추세 · 관찰 문구

> 작성일 2026-09-06 · 브랜치 `hr-recovery` · 상태: 구현 중

## 결정

- **권한**: `heartRateRecoveryOneMinute` 타입은 읽지 않는다. `heartRate` 샘플 권한으로 종료 후 180초 샘플을 직접 읽어 계산한다. 새 권한 없음. 워치 있을 때만 데이터가 생긴다.
- **정의**: 종료 심박 = 워크아웃 마지막 30초 평균. HRR1 = 종료 심박 − 종료 60초 후 심박(±15초 샘플 중앙값). HRR2 동일(120초).
- **표시 조건**: 종료 심박 ≥ 추정 최대심박(208−0.7×나이)의 70%. 최대심박 미상이면 130bpm 이상. 걷기로 마친 러닝은 회복량이 작게 나오는 게 당연해 숫자가 오해를 부른다. 임계는 임의로 정함.
- **근거**: Daanen 2012 (Int J Sports Physiol Perform 7(3):251–260, 체계적 문헌고찰) — 훈련 상태 향상 시 HRR↑, 단 종료 직전 강도·쿨다운 행동에 좌우. → 절대값 비교 금지, 종료 심박을 통제한 개인 추세만.
- **하지 않는 것**: 하루 단위 컨디션·피로 판정(근거 갈림), 대회 예측·레벨 반영, 임상 절단점(Cole 1999 12bpm) 인용.

## 1. 상세 심박수 패널

- `HRSeriesPanelChart` 아래에 "운동 후 심박수" 차트. 0~3분, 10초 버킷 min–max 막대, 빨강. 1분·2분 위치에 세로 점선과 "1분 −28" 라벨.
- 헤더 한 줄: "1분 만에 −28 bpm".
- 샘플 없음 · 조건 미달이면 섹션 자체를 그리지 않는다. "회복 데이터 없음" 문구 금지.
- 데이터: `HealthKitManager.fetchPostWorkoutHR(for:)` — 종료 후 180초 샘플, 디스크 캐시 `mimo_hrr_{id}.json`. 종료 1시간 이내 워크아웃은 워치 동기화가 안 끝났을 수 있어 캐시하지 않는다.

## 2. 성장 탭 추세

- `TrendMetric.hrRecovery1` 추가 → 스파크 카드·시계열 시트가 기존 경로로 생긴다. 라벨 "1분 회복", 단위 bpm, 높을수록 좋음, 색 심박 빨강.
- 히스토리: `fetchRecoveryHistory(from:)` — 최근 12개월 러닝마다 종료 30초 심박 + 종료 후 180초 샘플을 조회해 (날짜, 종료심박, HRR1) 저장. 캐시 `mimo_hrr_history.json`, 새 러닝(종료 1시간 경과)이 캐시 시각 이후에 있으면 재계산. 메트릭 히스토리 캐시 무효화 목록에도 포함.

## 3. 관찰 문구 (성장 탭, 폼 관찰 카드 아래)

- 잔차: HRR1 ~ 1 + 종료심박 (선형, 개인별 최소자승). 최근 12개월, 관측 16개 이상(임의).
- 판정: 기존 `mrFormShift` 재사용 — 최근 3개월 vs 이전 3개월, MDC₉₅ 또는 4주 연속.
- 문구는 **좋아진 쪽만**: "같은 심박으로 끝낸 러닝에서 1분 회복이 3개월 새 6bpm 늘었어요." 나빠진 쪽은 침묵(레벨 하락과 같은 태도). 근거 줄: "잔차 Δ+6.2bpm · MDC 3.1 · n 58/51 · Daanen 2012".

## 4. 테스트

`MRRecoveryTests`: 종료 심박 평균 · t±15초 중앙값과 nil · 조건(70%·130) · compute · 잔차 회귀가 종료심박 효과를 제거하는지 · 관찰 문구는 개선일 때만.
