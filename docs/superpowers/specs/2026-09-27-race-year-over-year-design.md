# 같은 대회 · 같은 거리 대회 해마다 비교 — A단계(결과 비교) 설계

작성일: 2026-09-27 · 브랜치: crew · 상태: 설계 합의, 구현 계획 `docs/superpowers/plans/2026-09-27-race-year-over-year.md`

## 배경과 목적

가민·삼성과의 차별은 점수와 처방이 아니라 **한국 대회로 잇는 과거·오늘·내일**에서 나온다(메모 `product-direction-engine`).
이 기능은 대회를 뛴 날 "지난번의 나"와 비교해 준다. 전체 계획은 C 방식이다.

- **A. 결과 비교(이 문서)** — 대회가 끝난 뒤 같은 대회의 지난해, 같은 거리의 지난 대회와 기록을 비교한다.
- **B. 준비 비교(다음 문서)** — 대회를 준비하는 동안 "작년 이 대회 3주 전"과 지금의 준비 상태를 비교한다. A가 만든 대회 쌍을 기준으로 쓴다.

## 범위

| 포함 | 제외 |
|---|---|
| 대회 DB에 시리즈 칸 추가와 1차 채움 | 더위 보정 |
| 같은 대회의 과거 해 찾기(비교 시점에만) | 과거 러닝 전체 대회 인식 백필 |
| 인사이트 카드 부연 줄 비교 문장 | 코스 변경 표시 |
| 대회 탭 비교 섹션 확장 | 직접 입력으로 과거 대회 등록 |
| 같은 거리 기준 10% | 경로 없는 러닝(가민 등)의 대회 인식 |
| | 나 탭 참가 대회 목록(별도 설계 문서) |

## 1. 표시 위치

대회로 확정된 러닝의 활동 상세 화면, 두 곳.

1. **오늘의 인사이트 카드의 부연 줄.** 지금은 `춘천마라톤 · 풀코스`로 바로 아래 깃발 줄(`대회 러닝 · 춘천마라톤`)과 이름이 겹친다. 비교할 과거 대회가 있으면 이 줄을 비교 문장으로 바꾸고, 종목은 깃발 줄 끝으로 옮긴다. 과거 대회가 없으면 지금 그대로.
2. **러닝 인사이트 섹션 대회 탭의 비교 섹션.** 지금의 "같은 거리 대회 비교"(날짜·페이스·심박)를 확장한다. 새 레이아웃을 만들지 않고 기존 섹션의 행 내용과 묶음만 바꾼다.

러닝 인사이트 섹션의 기본 탭은 **지금대로 리듬**이다. 비교 표는 대회 탭을 눌러야 보이고, 요약은 부연 줄이 맡는다.
공유 카드는 인사이트 **제목**만 쓰므로 부연 줄 변경이 공유 카드에 영향을 주지 않는다.

## 2. 비교 대상 찾기

### 2-1. 같은 대회 — 시리즈 칸

대회 DB(번들 CSV)는 해마다 별개의 줄이고 표기가 제각각이다. 예: `제45회 조선일보 춘천마라톤`(2024) · `제46회 조선일보 춘천마라톤`(2025) · `2026 춘천마라톤`(2026). 반대로 이름에 "춘천"이 들어간 다른 대회가 5개 있다. 앱이 실행 중에 이름을 추측하지 않는다.

- CSV 끝에 `series` 칸을 추가한다. 같은 대회는 같은 값. (구현 계획에서 변경: **모든 줄에 규칙 키를 채운다** — 새 연도 대회가 이름이 같으면 자동으로 이어진다. 키는 한글 정규화 이름, 예: `조선일보춘천마라톤`. 도구 `tools/race_series.py`, 수동 지정 `tools/race_series_overrides.tsv`.)
- **채우는 방법(개발 시 1회, 새 연도 추가 때마다 반복):**
  1. 규칙으로 1차 채움 — 이름에서 앞·뒤 연도, `제N회`, 띄어쓰기, 끝의 `대회`, 괄호를 떼고 같은 이름끼리 묶는다. 2026-09-27 시험에서 연도·회차·띄어쓰기만으로 43개 대회가 해를 넘어 묶였다.
  2. 남은 후보는 사람이 확인 — 날짜가 2주 안이고 출발지가 가까운데 이름이 다른 쌍을 목록으로 뽑는다. 주최(조선일보)·수식어(국제·경기·전국·혹서기)가 다른 쌍, 이름이 실제로 바뀐 쌍(JTBC 서울마라톤 → JTBC 마라톤, 출발지도 잠실 → 상암)이 여기에 해당한다. 시험에서 약 17쌍.
- **2023·2024년 대회는 사용자가 목록을 주면 DB에 추가**한다. 필요한 정보: 날짜·종목 거리(인식 기본 조건), 출발지 주소(좌표가 없으면 인식 불가), 출발 시각(없으면 자동 확정 안 됨). 추가하면서 시리즈 값도 함께 채운다.

### 2-2. 같은 대회의 과거 해 찾기 — 비교할 때만

대회 인식은 지금 러닝 상세를 열 때만 돈다. 과거 러닝 전체를 훑지 않으므로, 과거 해 대회가 DB에 있어도 그 러닝을 열어 보기 전에는 확정되지 않는다. 비교 시점에 필요한 범위만 찾는다.

오늘 확정된 대회 M(이름·날짜·공식 종목 거리)에 대해:

1. M의 DB 줄을 이름과 날짜로 찾아 시리즈 값을 읽는다. 없거나 빈칸이면 같은 대회 비교는 건너뛴다.
2. 같은 시리즈의 과거 날짜 DB 줄을 최신순으로 본다. 줄마다:
   1. 그 대회 이름·날짜로 이미 확정된 러닝이 있으면 그대로 쓴다.
   2. 없으면 그날 러닝 중 이 대회 한 개에 대해 기존 게이트(날짜·종목 거리 ±5%·출발 시각 ±90분·출발점 반경)를 검사한다. 출발 좌표는 상세 캐시에서, 없으면 해당 러닝의 경로만 HealthKit에서 읽는다.
   3. 기존 자동 확정 기준(venue 정밀도·시각 ±45분·종료점)을 통과하면 **자동 확정해 저장**하고 비교에 넣는다.
   4. 게이트만 통과하면 대회 탭 비교 섹션에서 한 번 묻는다: `2025 춘천마라톤 기록이 이 러닝인가요? [맞아요] [아니요]`. 맞아요 → 확정·저장, 아니요 → 기존 "대회 아님" 처리(재질문 없음).
   5. 사용자가 이미 "대회 아님"으로 표시한 러닝은 건너뛴다.
3. M과 같은 종목 거리의 러닝만 남긴다(풀은 풀끼리, 10K는 10K끼리).

### 2-3. 같은 거리 대회

- 확정된 대회 중 **공식 종목 거리가 M과 10% 이내**인 것. 확정 대회에는 GPS 거리가 아니라 공식 종목 거리가 저장되므로 GPS 오차와 무관하다. 10%는 20K·11K·40K 같은 비표준 종목을 표준 거리에 붙이는 범위다(기존 15% → 10%).
- 같은 시리즈로 이미 나온 대회와 M 자신은 뺀다.
- 최신순 최대 5줄.

## 3. 비교 숫자

- **공식 종목 거리가 정확히 같으면 완주 시간 차이.** 완주 시간 = 러닝 기록의 시간.
- **다르면 km당 페이스 차이와 실제 종목 거리.** 페이스 = 완주 시간 ÷ 공식 종목 거리.
- **더위 보정 없음.** 같은 대회는 대부분 같은 시기라 보정 없이 비교한다.
- **기온은 표의 행 끝에 표시만** 한다(러닝 기록의 기온). 없으면 칸을 비운다.

## 4. 문장 규칙(부연 줄)

비교 대상은 하나만 고른다.

1. 같은 대회의 가장 최근 해
2. 없으면 같은 거리의 가장 최근 대회
3. 둘 다 없으면 지금처럼 `대회명 · 종목`

기획서의 좌절 방지·"하락은 조용히" 원칙에 따라:

| 경우 | 한국어 | 영어 |
|---|---|---|
| 같은 대회, 1년 전, 빨라짐 | 작년보다 4분 12초 빨라요 | 4:12 faster than last year |
| 같은 대회, 2년 이상 전, 빨라짐 | 2024년보다 4분 12초 빨라요 | 4:12 faster than 2024 |
| 같은 거리, 같은 종목 거리, 빨라짐 | 지난 서울마라톤보다 6분 30초 빨라요 | 6:30 faster than your last 서울마라톤 |
| 같은 거리, 다른 종목 거리, 빨라짐 | 지난 ○○ 20K보다 km당 8초 빨라요 | 8 s/km faster than your last ○○ 20K |
| 느려짐 또는 같음(같은 대회) | 작년 춘천마라톤 3:56:22 | Last year's 춘천마라톤: 3:56:22 |
| 느려짐 또는 같음(같은 거리) | 지난 서울마라톤 3:58:40 | Last 서울마라톤: 3:58:40 |

- "빨라짐"은 시간 차이 1초 이상(페이스는 km당 1초 이상). 그 외는 느려짐 또는 같음 줄.
- 문장 속 대회 이름은 앞·뒤 연도와 `제N회`를 뗀 표시 이름을 쓴다(2-1의 규칙과 같은 함수).
- 표(5장)는 빨라졌든 느려졌든 차이를 사실대로 보여 준다.

## 5. 대회 탭 비교 섹션

섹션 제목 `같은 대회 · 같은 거리`. 묶음 두 개, 묶음 안은 최신순, 오늘 행은 지금처럼 바이올렛 강조.

```
같은 대회
  2026.10  춘천마라톤     3:52:10   오늘        18°C
  2025.10  춘천마라톤     3:56:22   +4:12       24°C
  [2024 춘천마라톤 기록이 이 러닝인가요?  맞아요 · 아니요]
같은 거리
  2026.03  서울마라톤     3:58:40   +6:30       9°C
  2025.11  ○○ 40K         3:41:05   km당 +5초   12°C
```

- 차이 부호는 과거 행 기준 "오늘보다 얼마나 느렸나"(+는 오늘이 더 빠름).
- 과거 대회가 하나도 없으면 섹션을 숨긴다(지금은 같은 거리 2개 이상일 때만 보임 → 과거 1개 이상이면 보임).

## 7. 테스트

컴파일 확인은 `build-for-testing`까지(시뮬레이터 실행 없음, 메모 `feedback-no-simulator`). 순수 로직 단위 테스트:

- 시리즈 찾기: 이름·날짜로 DB 줄, 빈 시리즈는 같은 대회 없음.
- 같은 거리 10%: 21.0975와 20.0은 포함, 10.0과 11.5는 제외.
- 부연 줄 대상 우선순위: 같은 대회 > 같은 거리 > 없음.
- 문장: 1년 전·2년 전·같은 거리 같은 종목·다른 종목·느려짐·같음, 한/영.
- 표 차이 부호와 "빨라짐" 1초 경계.
- 과거 해 판정: 자동 확정 기준 통과 → 확정, 게이트만 통과 → 질문, 대회 아님 표시 → 건너뜀.

## 진입점 — 나 탭 참가 대회

별도 설계 `2026-09-27-my-races-entry-design.md`로 확정했다. 성장 탭 `예측이 얼마나 맞았나`를 없애고 나 탭 `참가 대회`에 `예정 | 기록` 토글을 둔다. 기록 행을 누르면 러닝 상세로 가서 이 문서의 비교를 본다. 기록 행의 `N회째`는 이 문서의 시리즈 칸을 쓴다.

## 구현 계획에서 확정한 세부(2026-09-27)

- 같은 해에 두 번 열리는 대회(예: 한강 서울 하프 1월·8월)는 "작년" 대신 "지난 ○○" 문장.
- 과거 러닝 확인 질문은 날짜를 넣는다: `2025 춘천마라톤 — 10월 25일 러닝이 이 대회였나요? [맞아요] [아니요]`.
- 봄·가을이 다른 인천마라톤은 수동 지정으로 분리. 사용자 확인 대기 후보 4쌍: 남산우정(↔산불조심 한국남산우정) · 울진 금강송배(↔금강송힐링) · 청주 무심천(↔무심천 투데이 토·일) · 전마협 금산(↔금산 인삼).
