# 오늘의 인사이트 내보내기 + 아침 제안 설계

- 날짜: 2026-10-15
- 상태: 진행 승인(사용자 "진행") · 수치 표시는 기본 숨김(사용자 미응답 → 개인정보 보호 쪽 기본값)
- 관련: `2026-09-22-morning-readiness-design.md`(아침 제안), 메모리 morning-readiness-followups

## 1. 목적
내보내기 이미지 = **달린 후 내용(지금 카드 그대로)** + 그 아래 **아침 제안**.
- **그날 아침 → 실제**: 러닝 전에 앱이 줬던(또는 줬을) 제안 + 실제로 어떻게 뛰었는지 한 줄. 당일에도 항상 가능.
- **다음 날 아침**: 러닝 다음 날 아침 제안. 그 밤 수면·HRV가 들어온 뒤(기상·동기화 후) 내보낼 때만.

## 2. 데이터 원칙 — 저장 + 재계산
- **저장(스냅샷)**: 홈에서 아침 제안이 화면에 보일 때(`MRTodayCardView` onAppear) 그날 날짜 키로 저장. 앱이 실제로 보여 준 문장을 보존.
- **재계산**: 스냅샷이 없으면 내보낼 때 `mrReadiness(asOf:)`로 그 시각 기준 다시 계산. 건강 앱 기록은 남으므로 앱을 안 열었던 날도 가능.
- 우선순위: 그날 아침 = 러닝 시작 전에 찍힌 스냅샷 → 없으면 재계산. 다음 날 아침 = 그날 스냅샷 → 없으면 재계산 → 그 밤 HRV가 아직 없으면(`hrvPending`) 블록 대신 탭 요약의 "→ 다음 방향" 줄.
- 새 판정 없음 — 엔진 `mrReadiness` 결과만 쓴다.

## 3. 재계산 기준 시각(asOf)
| 블록 | asOf | 러닝 필터 |
|---|---|---|
| 그날 아침 | 러닝 시작 − 1초 | `start < asOf` (그날 러닝 제외 — 엔진의 "이미 뛴 날 nil" 회피) |
| 다음 날 아침 | min(다음 날 첫 러닝 시작 − 1초, 다음 날 12:00, 지금) | `start < asOf` |

엔진 쪽 손볼 곳(조사 결과): 그 주 러닝 집계(`mrSessionSuggestion` :177, taper :449), d=0 포함 집계(:256, :304, MRHRVTrend :201)가 asOf 이후 러닝을 세지 않도록 호출부에서 `runs`를 미리 거른다. `hardRunStarts`는 오늘−15일만 있으므로 재계산 시 asOf 기준 14일을 `RunSummaryBuilder.isHardRun`으로 다시 만든다. 계획 주차·LT1·이지 페이스는 현재 모델을 쓴다(한계 — 스냅샷이 있으면 그쪽 우선).

## 4. 화면(내보내기 이미지 맨 아래 한 블록)
```
아침 제안                                         ← 섹션 라벨
☀ 그날 아침 · 이지런                               ← 판정 색(초록/노랑/주황) = 홈과 같은 색
  연속 4일째입니다. 강도를 빼고 몸을 풀어 주세요.    ← why 첫 문장
  → 실제: 이지 페이스 유지 · Zone 1~2 85%           ← 탭 요약 리듬 블록 첫 문장(short)
☾ 다음 날 아침 · 강도 OK                          ← 다음 날 데이터 있을 때만
  어젯밤 HRV가 평소 범위입니다 …
```
- 수치 줄(`data`: HRV ms·안정시심박·연속일 등)은 **기본 숨김**. 내보내기 시트에 "수치 표시" 칩(켜면 data 줄 추가).
- 다음 날 데이터가 없으면 그 줄 대신 "→ 다음: " + 탭 요약 방향(있을 때).
- 위치: 기존 카드(exportHeader + cardBody) 아래. 탭(리듬·폼·퍼포먼스)과 무관하게 같은 블록. 대회 탭에도 붙인다.
- 4:5 고정(ShareCanvas.fit)이라 길어지면 전체 축소 — why는 첫 문장만, 블록 최대 6줄.

## 5. 구현 범위
1. `MRReadinessSnapshot`(SwiftData @Model, CloudKit 기본값 규칙): dateKey "yyyy-MM-dd", level, line, why, data, planLine, computedAt. 홈 `MRTodayCardView` onAppear에서 upsert(같은 날 마지막 표시본, 단 그날 첫 러닝 시작 이후에 찍힌 건 '그날 아침'으로 쓰지 않음).
2. `MREngineStore.readiness(asOf:runs:hardRunStarts:)` 공개 메서드 — buildTodayCard와 같은 입력을 asOf 기준으로 모아 `mrReadiness` 호출. runs는 `start < asOf`로 거른다.
3. `InsightMorningSection`(뷰) + 조립기 `InsightMorning.make(...)` — 위 우선순위로 그날/다음 날 블록 모델 생성.
4. `InsightExportSheet`: engine 환경 객체 접근, 블록 추가, "수치 표시" 칩.
5. 테스트: 조립기 우선순위(스냅샷 우선 · 러닝 이후 스냅샷 제외 · 다음 날 pending → 방향 줄) / asOf 러닝 필터 / 스냅샷 날짜 키.

## 6. 한계
- 재계산은 HRV 60일 보관 한계로 약 25일 이전 러닝은 다음 날·그날 HRV 판정이 빠질 수 있다.
- 계획·LT1·이지 페이스는 현재 값 — 스냅샷이 없는 날은 당시와 다를 수 있다.
- 강도 러닝 습관(intenseRuns, 오늘 기준 84일)·최근 인터벌(오늘 기준 3건)은 오늘 창이라, 며칠 이상 지난 러닝을 재계산하면 습관 간격·리듬 제안이 당시와 다를 수 있다(당일·다음 날 내보내기에는 영향 미미).
- 실기기 확인 필요: 홈을 연 날 스냅샷 저장 · 앱을 안 연 날 재계산 · 저녁 러닝 당일 내보내기(다음 날 블록 없음) · 다음 날 아침 내보내기.
