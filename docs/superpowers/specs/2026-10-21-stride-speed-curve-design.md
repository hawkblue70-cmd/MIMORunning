# 보폭 기준을 개인 속도 곡선으로 교체 — 설계 (2026-10-21)

> 근거: [검증 설계](2026-10-21-form-speed-curve-validation.md)의 실기기 결과(195회).
> 보폭 walk-forward 오차 구간 0.010 / 곡선 0.006m(40%↓) · 작은 구간 0.019 / 0.004.
> 케이던스·수직진폭은 비김, 지면접촉은 구간이 나음 → **보폭만** 바꾼다.

## 1. 문제

보폭은 속도를 그대로 따라간다(속도 = 케이던스 × 보폭). 구간 방식은 6'23"~6'40" 같은 구간 하나에
중앙값 하나를 쓰므로, 구간 안에서 느린 쪽 러닝은 "보폭이 평소보다 작았습니다"가 된다.
실제 사례: 10/11(7'00", 0.847m — 구간 0.866~0.895 '아래', 곡선 0.839~0.861 '범위'), 10/16(6'40", 0.880m).

## 2. 바꾸는 것 / 안 바꾸는 것

**바꾼다 — 그 러닝의 보폭 "평소 범위"(FormStat) 하나**
보폭 FormStat을 쓰는 곳이 모두 같은 값을 받게, 지면접촉 시점 보정(`displayGctStat` / `driftAdjustedGCT`)과 같은 방식으로
**표시용 보폭 Stat 한 곳**을 만들고 소비처는 그것만 읽는다.

| 소비처 | 지금 | 바뀐 뒤 |
|---|---|---|
| 폼 카드 범위 바 (`RunFormCardView` chainChildren) | `displayBb?.strideLength` | `inputs.displayStrideStat` |
| 폼 카드 km 차트 띠 (`RunFormCardView` 보폭 시리즈) | `dispBb?.strideLength` | `x.displayStrideStat` |
| 폼 문장·장거리 문장 (`TabDigestForm` 177·217) | `bb?.strideLength` | `x.displayStrideStat` |
| 인사이트 탭 폼 문장 (`RunInsightTabCard` 2091·2123·2198) | `bb.strideLength` | 같은 헬퍼 |
| 단계 표 (`FormPhase.bandStats`) | `b.strideLength` | 단계 페이스에서의 곡선 Stat |

**안 바꾼다**
- 케이던스·지면접촉·수직진폭 기준 (검증에서 이득 없음).
- 주법 판정(잔발형·큰보폭형: `cadenceStrideR`·잔차 분위수) — 구간 안 케이던스·보폭 잔차를 짝지어 보는 별개 지표. 보폭만 곡선 잔차로 바꾸면 두 축 기준이 어긋난다.
- 후반 진단의 페이스 보정(`LateRunDiagnosis.paceTrend`)·`FormPhase.strideWorsened` — 이미 자체 페이스 보정이 있다. 곡선 기울기로 바꾸는 건 별도 검증 뒤.
- 빈 원(거리 비슷한 최근 5회) 선택 규칙 — 같은 구간·거리 0.5~2배 그대로(아래 4장 참고).

## 3. 곡선 — 검증한 그대로 출시

검증에서 채택된 설정을 **바꾸지 않는다**. 출시 코드와 검증 코드가 같은 함수를 쓰게, 지금 DEBUG 안에 있는
`FormCurveFit`·`fitCurve`를 출시 코드(`Insight/FormSpeedCurve.swift`, Codable)로 옮기고 하네스는 그것을 호출한다.

- 식: 보폭 ~ 1 + x + x², x = GAP 속도(m/min) − 평균 속도. `MRLinAlg.lstsq`.
- 데이터: 기준선과 같은 입력(12개월·3km+·대회 제외), 최근 6개월 가중치 2배, 최소 25회.
- 범위: 기대값 ± 1.2 × 잔차 SD (구간 FormStat과 같은 1.2).
- 외삽 금지: 오늘 GAP 속도가 관측 속도 범위 밖이면 곡선을 쓰지 않는다(아래 폴백).
- 기준선 캐시에 저장: `RunningFormBaseline.strideCurve: FormSpeedCurve?` 추가, `currentVersion` 17 → 18(재계산 1회).

**FormStat으로 바꾸는 법** — 소비처가 모두 FormStat을 받으므로 새 타입을 퍼뜨리지 않는다.
`FormStat(median: 기대값, sd: 잔차 SD, count: n, p10: nil, p90: nil)`. p10/p90이 nil이면 "판정불가 띠(P10~P90)" 분기를 타지 않는다.

**폴백 (지금 동작 그대로)**
1. 곡선 없음(25회 미만 · 특이행렬) → 구간 `strideLength`.
2. 오늘 속도가 관측 범위 밖 → 구간(또는 기존 참고 밴드) `strideLength`.
3. 구간 판정불가·참고 밴드·인터벌 생략 규칙은 위에서 그대로 적용된다 — 곡선은 Stat만 바꾸고 판정 가능 여부 게이트는 건드리지 않는다.

**알려진 효과**: 검증에서 보폭 '범위 밖' 비율이 23% → 8%로 줄었다. 느린 날 보폭 경고가 사라지는 것이 목표였고,
그 대가로 범위가 구간보다 넓다. 출시 뒤 실기기에서 실제로 짧았던 날을 놓치는지 본다.

## 4. 화면 문구 (승인 필요)

범위 바 범례가 지금은 "회색 막대 = 내 평소 범위 (페이스 6'23"~6'40" 러닝 34회)"다. 보폭 막대만 기준이 달라지므로:

- **안 A (권장)** — 범례는 그대로, 보폭이 곡선일 때만 막대 아래 범례 끝에 한 줄:
  "보폭 막대 = 오늘 페이스 6'35" 기준 (러닝 195회)"
- 안 B — 범례 문구를 바꾸지 않음. 숫자만 바뀜(설명 없이 기준이 달라져 혼동 우려).

빈 원은 각 러닝의 실제 값 그대로 둔다(페이스 환산 값은 "실제 기록"이 아니라서). 그래서 빈 원이 막대 밖에 찍힐 수 있다 —
같은 구간 안에서 페이스가 달랐던 러닝. 이건 설명 없이 둬도 기존 범례("거리가 비슷한 최근 5회")와 모순되지 않는다.

## 5. 단계 표 (`FormPhase.bandStats`)

초반·중반·후반은 페이스가 다르다. 지금은 단계 페이스가 속한 구간 Stat을 쓰므로, 곡선은 **단계 페이스에서의 기대값**으로 준다
(같은 헬퍼에 단계 GAP 페이스를 넘김). 외삽·폴백 규칙은 2·3장과 같다.

## 6. 구현 순서

1. `FormSpeedCurve`(Codable) 출시 코드로 이동 + `strideStat(atPace:) -> FormStat?` · 하네스가 이것을 쓰도록 변경(검증=출시 동일 보장).
2. `FormBaselineEngine.compute`에서 보폭 곡선 계산·저장, 버전 18.
3. 공용 헬퍼 `FormNarrative.curveStrideStat(baseline:fallback:gapPace:)` — 소비처 5곳 교체.
4. 범례 한 줄(안 A, 승인 시).
5. 테스트: ① 관측 범위 밖이면 폴백 ② 25회 미만이면 폴백 ③ 같은 구간 안 느린 러닝이 곡선 기준 '범위' ④ FormStat 변환(p10/p90 nil, lower/upper = 기대값 ± 1.2SD) ⑤ 옛 캐시(v17)는 재계산.
6. 컴파일 확인(`build-for-testing`) → 실기기 확인 포인트: 10/11·10/16 보폭 문장이 사라지는지, 9/16·10/10 막대.

## 7. 열린 결정

- 4장 범례 안 A/B.
- 체감 확인(9/16·10/10·10/11·10/16에 보폭이 짧다고 느꼈는지) — 검증 설계의 채택 조건 중 남은 하나. 느꼈다면 교체 대신 범위 폭부터 다시 본다.
